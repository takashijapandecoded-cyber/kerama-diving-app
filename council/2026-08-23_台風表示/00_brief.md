# ブリーフ: 慶良間ダイビングアプリに台風情報を載せる

作成: 2026-08-23 深夜 / 全員がこの1本を読む。出力先だけ各自違う。

## 1. このアプリは何か

沖縄・那覇港から慶良間諸島へ毎日ボートで渡る**プロダイビングガイド（優くん）1人のための業務ツール**。
朝の「出港するか・やめるか」を1画面で判断するのが唯一の目的。お客様向けではない。

- 本番: https://kerama-diving.vercel.app
- 使う端末: **ほぼ100%スマホ（iPhone）。屋外・直射日光下・船上で見る。片手操作。**
- 見る時間: 朝5時にメールが届き、そのリンクから開く。出港準備の合間に数十秒。

## 2. いま解決したい問題

**アプリには台風を見る仕組みが一切ない。**
波高が上がることで間接的にスコアは下がるが、「なぜ荒れるのか＝台風」が画面のどこにも出ない。

沖縄では台風は年に何度も来る。船の係留・お客様へのキャンセル連絡・避難のタイミングは
「波が高い」ではなく「台風がいつどこに来るか」で決まる。**必須情報という判断。**

## 3. 使えるデータ（2026-08-23 に実際に取得して確認済み・すべて無料/登録不要）

### 3-1. 追跡中の台風一覧
`https://www.jma.go.jp/bosai/typhoon/data/targetTc.json`
```json
[{"tropicalCyclone":"TC2621","typhoonNumber":"2618","category":"TY","issue":"2026-08-23T21:45:00+09:00"}]
```
category: TY=台風 / TS=熱帯低気圧(暴風域なし相当) / TD=熱帯低気圧

### 3-2. 個別の台風の詳細
`https://www.jma.go.jp/bosai/typhoon/data/TC2621/specifications.json`

取れるもの（実況＋12/24/48/72/96/120時間後の予報、各時点で）:
- `name.jp` 台風の名前（例: ソウデル）
- `typhoonNumber` 台風番号（例: 2618 = 2026年第18号）
- `category.jp` 階級（台風 / 熱帯低気圧）
- `position.deg` [緯度, 経度]
- `pressure` 中心気圧 hPa
- `maximumWind.sustained["m/s"]` 最大風速、`.gust["m/s"]` 最大瞬間風速
- `stormWarning[].range.km` **暴風域の半径 km**
- `galeWarning[].range.km` 強風域の半径 km
- `course` 進行方向（例: 北西） / `speed` 進行速度
- `location` 現在地の呼称（例: 日本の南）
- `probabilityCircleRadius.km` 予報円の半径
- `validtime.JST` その予報が有効な時刻

### 3-3. 暴風域に入る確率（★これが一番強い）
気象庁XMLフィード `https://www.data.jma.go.jp/developer/xml/feed/extra.xml` の中の
`VPTA5x` ファイル。**「慶良間・粟国諸島」(コード 471013) という区分がそのまま存在する。**
自分で距離を計算する必要がない。台風ごとに1ファイル（EventID で対応づけ）。

## 4. いまの画面の作り（変えてはいけない前提）

横スワイプの4ページ構成。台風を載せるのは **PAGE 0「🌊 今日」** を想定。
上から順に:

```
[画面最上部] #go-nogo-banner   … 固定バナー。「✅ 出港OK（要現地確認）」等。高さ3rem
              #page-dots / #page-labels … ページ切替のドットとラベル
              #hero-location  … 「🤿 慶良間諸島 ダイビングコンディション」
              #hero-date      … 「2026年8月23日(日)」
              #warning-chips  … 気象庁の警報・注意報チップ（後述）
              #score-container … ★コンディションボード（大きな円形スコア＋内訳5個）
              以下、那覇港沖 / 航路中間 / 慶良間沖 の3カード
              NASA衛星画像、データ更新時刻、免責文
```

### 既存の警報チップ（`#warning-chips`）のパターン
```html
<span class="warn-chip warn-none">✅ 警報・注意報なし</span>
<span class="warn-chip warn-advisory">⚡ 雷注意報</span>
<span class="warn-chip warn-warning">🌀 暴風警報・慶良間</span>
```
**4状態を必ず出し分ける**という原則がある（取得失敗 / 更新停止 / 発表なし / 発表あり）。
「何も出さない」は禁止。取得失敗と平穏の区別がつかなくなるため。

### CSS変数（必ずこれを使う。新しい色を勝手に増やさない）
```css
--bg:#0a1628  --surface:#1a2744  --surface2:#243358  --accent:#00b4d8
--text:#e2e8f0  --muted:#94a3b8  --border:rgba(148,163,184,0.15)
--go:#22c55e   --caution:#f59e0b  --danger:#ef4444   --radius:12px
```
ダーク基調。背景に地球の衛星写真が薄く敷かれている。

## 5. 制約（守れていないものは不採用）

1. **幅375pxのiPhoneで破綻しないこと。**横スクロールを起こさない
2. **屋外・直射日光下で読める**こと。細い字・薄い色・小さすぎる字を避ける
3. **タップできる要素は44px以上**（過去にUX指摘を受けて修正した経緯あり）
4. **文言は標準語。**方言・砕けすぎた表現は不可。専門用語は避けるか、その場で言い換える
5. **既存のCSS変数の範囲で作る。**外部ライブラリ・外部画像・Webフォントの読み込み禁止
6. **台風がないときに場所を占有しない**こと。年の大半は台風がいない
7. **煽らない。**優くんはプロ。脅す表現ではなく、判断に必要な事実を淡々と出す
8. **アプリ本体のファイルは絶対に編集しない。**指定された自分の出力先だけに書く

## 6. 考えるべき論点（答えは各自で出す）

- 置き場所はどこか。コンディションボードの直下か、その上か、警報チップと並べるか、
  最上部のバナーと統合するか。**理由とセットで。**
- 平常時（台風ゼロ）はどう振る舞うか。消すのか、「台風なし」と出すのか
  （既存の警報チップは「✅ 警報・注意報なし」と明示する流儀）
- 複数の台風が同時にあるとき、全部見せるか、慶良間に関係あるものだけか
- 「まだ遠い台風」と「明後日に暴風域」をどう描き分けるか
- 進路を図で見せる価値はあるか。文字だけで足りるか
- タップして詳細を開く形にするか、最初から全部出すか

## 7. 提出物

指定された**1つのHTMLファイル**に、以下を1枚にまとめて書く:

1. **モックアップ本体**を最低3状態、実寸375px幅で並べて描く
   - 状態A: 台風なし（平常時）
   - 状態B: 台風はあるが遠い（8/23時点＝1301km・確率0%）
   - 状態C: 暴風域が確定的（8/26＝196km・確率96%・波8.5m）
   - 余力があれば「取得失敗」も
2. 各モックアップの**下に短い説明**（なぜこの形か、どこに置くか、平常時どうなるか）
3. 最後に**自分の設計方針を3〜5行**で

- 単体で開いて成立するHTML1枚（CSSはstyle要素に内包）。JSは無くてよい
- 実際のアプリのダーク背景に置かれる前提で、bodyの背景は `--bg` にする
- **375px幅を実寸で再現**すること（横に並べる場合は各枠を375px固定に）
- 日本語。文言は本番に載せられる品質で書く（後で流用する）

## 8. 禁止

- `index.html` `css/style.css` `js/` 配下など**本番ファイルの編集**
- 上記以外のファイルの作成
- 外部URLの読み込み（画像・フォント・CSS・JS すべて）
